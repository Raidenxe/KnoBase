## 2. 文档编写规范（公司标准摘要）

统一文档遵循以下格式约束，以保证结构清晰、相互链接、可追溯：

1. **元数据表**：每份文档首部须有「文档编号 / 密级 / 版本 / 适用范围 / 维护人 / 上次更新」（见本文档示例）。
2. **修订历史表**：记录版本、日期、修订人、变更摘要；重大变更需在文中标注。
3. **目录**：超过两个章节即附目录。
4. **章节编号**：使用“1./2./3./…”及子级“1.1/1.1.1”。
5. **术语一致性**：软件名称统一为「KnoBase RAG智能助手」；配置项统一以 `RAG_` 前缀环境变量为准。
6. **可追溯性**：涉及代码/接口的内容应给出文件路径或接口路径，便于回查。
7. **准确性**：与当前代码实现保持一致；判定不实或过时内容应修订或归档（见第 3 节流程）。

## 3. 文档生命周期（识别过时 → 处理）

- **识别**：对照 `app/` 实现与验收状态，凡描述“计划/预期/TODO/未勾选清单”且对应功能已落地者，判为过时规划稿。
- **处理**：过时规划稿移入 `archive/`（安全归档，不物理删除，以便追溯）；其有效结论并入对应统一文档；不实内容径行修正。
- **登记**：所有归档/新增/修订登记于 [文档更新记录](文档更新记录.md)。
