## 1. 概述

系统是一款面向软件维保场景的**端到端检索增强生成（RAG）问答系统**：用户以自然语言提问，系统从产品说明书知识库检索相关片段，交由大模型生成**带来源引用、可追溯**的回答，并通过多重防幻觉策略降低臆造概率。

核心目标：回答准确、来源可溯、可维护、可评估。

## 2. 技术栈与分层

```
┌─────────────────────────────────────────────────────────────┐
│  前端（静态页）  login / index(聊天) / browser(知识库)        │
│                  admin(控制台) / share(分享)                  │
├─────────────────────────────────────────────────────────────┤
│  API 层  app/api/routes  （chat / documents / conversations  │
│          / auth / categories / feedback / shares / tasks     │
│          / observability / notifications / tickets / ws）     │
├─────────────────────────────────────────────────────────────┤
│  业务服务层  app/services  （history / auth_store / shares    │
│          / versions / trace_store / notify / ticket /        │
│          / resource_monitor / prompt_store / metrics …）      │
├─────────────────────────────────────────────────────────────┤
│  核心引擎层  app/core    （llm / embeddings / milvus_store / │
│          retrieval / bm25 / rerank / security / access /     │
│          tracing / config / runtime_config）                  │
├─────────────────────────────────────────────────────────────┤
│  知识图处理  app/knowledge（loader / splitter / pipeline）     │
│  对话编排    app/graph   （state / nodes / builder）          │
├─────────────────────────────────────────────────────────────┤
│  存储        Milvus(向量) + SQLite(历史/账号/版本/审计/工单…)  │
└─────────────────────────────────────────────────────────────┘
```

- **Web 框架**：FastAPI（REST + SSE 流式 + WebSocket）。
- **对话编排**：LangGraph（Corrective-RAG：问题改写 → 检索 → 相关性精筛 → 生成 → 事实校验 → 追问）。
- **向量库**：Milvus（单机用 milvus-lite），`manual_chunks` 集合，维度 512（bge-small-zh-v1.5）。
- **Embedding**：fastembed（本地 ONNX 离线）或 OpenAI 兼容 API。
- **LLM**：OpenAI 兼容 API（GLM/GPT/Qwen…）；未配置 API Key 时回退 Mock 离线抽取式演示。
- **辅助存储**：SQLite（对话历史、账号/角色、文档版本、分享、审计、用量、工单通知、资源曲线、提示词）。

## 3. 请求主链路（问答）

```
用户提问
   │  GET/POST /api/v1/chat/stream
   ▼
LangGraph 编排（app/graph/builder.py）
  1. 意图/改写         → 对过长或多轮模糊问题进行改写
  2. 检索 retrieve      → 向量召回 + BM25 + RRF 融合 + 可选 rerank
  3. 相关性精筛 grade   → 低于极小值的片段丢弃（防误导）
  4. 生成 generate      → 注入检索片段 + System Prompt，输出 Markdown 与引用编号
  5. 校验 verify        → 回答关键陈述与来源片段一致性；失败则重试/拒答
  6. 追问               → 生成 follow-up 建议
   ▼
SSE 流式返回（token / status / reset / done / error）
```

链路任一步骤耗时均写入 TraceStore，供 `/traces`、`/traces/{id}/detail` 拆解。

## 4. 知识处理流水线

```
数据源
 ├─ 批量目录 data/manuals  → IngestPipeline 增量导入（按 名称+大小+mtime 指纹跳过未变）
 ├─ API 上传 /upload        → ≤20MB，PDF/Word/TXT/MD
 ├─ 目录扫描 /scan          → 支持 background 异步（tasks 进度上报）
 └─ 网页抓取 /web-import    → 拉取公开文档，正文降噪

加载 loader → 分块 splitter(chunk_size=480, overlap=64, 按标题切节) → 向量化 embedding
→ 写入 Milvus(含 tenant_id / doc_id / chunk_index / section_path / page)
```

增量导入避免每次启动全量向量化；异步导入不阻塞问答服务。

## 5. 认证、多租户与授权

- 开关 `RAG_AUTH_MODE`：`off`＝演示免登录；`on`＝生产 JWT 认证。
- 四角色：`admin` / `owner` / `member` / `viewer`。
- 守卫：`read_required` / `write_required` / `admin_required` / `owner_required`（见 [RBAC](rbac.md)）。
- 租户隔离：Milvus `tenant_id`、对话历史、文档版本均按租户隔离。
- 文档分类授权：用户组 → 分类的授权矩阵（`app/core/access.py`）。

## 6. 运维与可观测性（“运维四件套”）

| 能力 | 实现 |
|---|---|
| 链路追踪 | TracingMiddleware 生成 trace_id，TraceStore 内存环形缓冲 + trace.db 可选落库 |
| 接口性能 | 中间件埋点采集 P50/P95/P99/QPS（`/metrics/endpoints`） |
| 运行时动态配置 | `runtime_config.py` 支持热切换 LLM/Embedding/检索参数（`/admin/models`、`/admin/retrieval`） |
| 资源水位 | `resource_monitor.py` 采样 CPU/内存/磁盘，24h 曲线（`/admin/resource/*`） |
| 慢请求 | 全程耗时 > 阈值入明细（`/admin/slow-requests`） |
| 审计 | 敏感操作（角色/启用/授权/参数变更）落 `audit.db`（`/audit`） |

## 7. 版本管理

文档覆盖上传/增量更新时，为其建立修订版本（`versions.db`），支持查看修订历史、指定版本快照与回滚；回滚后生成新修订。详见 [Versioning](versioning.md)。

## 8. 评估基线

- 评估指标：Hits@k / Precision@k / Recall@k / MRR@k（`app/eval/registry.py`）。
- 数据集：`eval/dataset.jsonl`；离线脚本 `scripts/eval.py`。
- 检索参数精校脚本：`scripts/tune_retrieval.py`（网格搜索，见 [模型参数精校报告](模型参数精校报告.md)）。

## 9. 设计要点与限制

- **防幻觉**：相关性阈值、关键词覆盖率双重过滤、含来源的一致性校验、低置信拒答。
- **Mock 回退**：未配置实际 LLM Key 时仅验证链路，生成质量不代表真实模型。
- **多用户会话隔离**：当前会话按租户隔离；多用户同租户内私有会话建议启用按 user 隔离（见改进建议）。
